ESQUEMA ROOM FINAL (1=1 cobro)
-------------------------------
clients(id PK auto, name, email UK, phone, created_at)
budgets(id PK auto, code UK ej #00125, clientId FK->clients CASCADE,
 date long, descripcion_servicio text libre, total_amount double,
 status BORRADOR/ENVIADO/APROBADO/RECHAZADO, created_at)
budget_items(id PK auto, budgetId FK->budgets CASCADE, descripcion text libre,
 cantidad double, unidad_medida [unid,hs,m,cm,m2,ml,kg,g,l,caja,global,servicio],
 precio_unitario double; subtotal=cantidad*precio, total=suma directa sin IVA)
receivables(id PK auto, code UK, clientId FK->clients CASCADE,
 budgetId FK->budgets UNIQUE CASCADE => 1 cobro=1 presupuesto,
 amount, due_date long, status PENDIENTE/VENCIDO/PAGADO)

REGLAS NEGOCIO
--------------
- Servicios e items texto libre. Total = suma subtotales.
- addBudget(): inserta budget+items y AUTO-crea cobro espejo mismo code,
  PENDIENTE, vence +30d. Devuelve -1 si cliente inexistente o code duplicado.
- addReceivable(manual): exige code == presupuesto existente, si no devuelve -1
  y la UI avisa. addClient(): email UK, devuelve -1 si duplicado.
- getBudgets()/getClients()/getReceivables() leen Room y mapean a modelos con
  dbId/clientId/budgetId + contadores calculados (no guardados).
- updateBudgetStatus()/updateReceivableStatus() persisten cambios de estado.
- Seed solo si clients vacía: Pedro García, María López + #00125 con 1 item + cobro.
